# 기능 명세

이 문서는 `llm-wiki`의 공개 기능 명세다. 세부 API는 [API 명세](./api-spec.md), 설치 절차는 [설치 매뉴얼](./setup-manual.md), 실제 사용 흐름은 [사용자 매뉴얼](./user-manual.md)을 기준으로 본다.

## 제품 경계

`llm-wiki`는 사람이 입력한 자유 메모를 AI가 구조화된 지식 노트로 바꾸고, 사용자가 그 결과를 검토하며 다시 검색과 대화에 활용하는 개인 지식 워크벤치다.

현재 핵심 경로는 웹 워크벤치다.

- `/notes`에서 메모를 작성하고 저장한다.
- `AI로 처리` 또는 `AI 재분석`으로 source note를 생성하거나 갱신한다.
- 태그, 주제, 대상, 일정 후보는 AI가 제안하고 사람이 승인한다.
- 승인된 연결과 일정은 DB에 저장되고 필요하면 Markdown mirror로 내보낼 수 있다.

## 주요 기능 영역

| 영역 | 설명 |
| --- | --- |
| 노트 작성 | 제목 없이도 본문 중심으로 메모를 남길 수 있다. |
| AI 처리 | 메모를 읽기용 정리와 구조화 분석으로 바꾸고, 사실, 태그, 주제, 대상, 일정 후보를 만든다. |
| 제안 검토 | 제안 메뉴 또는 노트 우측 패널에서 승인/거절한다. |
| 문서 피드백 | 소스 노트에 사람이 피드백을 남기고 재처리한다. |
| 일정/알림 | 일정, 마감, 예약, 후속 확인 후보를 등록하고 알림을 받는다. |
| 대화형 검색 | 자연어 질문으로 노트, 일정, 알림을 함께 찾는다. |
| Markdown mirror | DB 내용을 감사용 Markdown 파일로 내보낸다. Legacy 설정에서는 Git mirror로 push할 수 있다. |
| 첨부파일 | MinIO/S3 호환 저장소에 파일을 올리고 노트와 연결한다. |
| 운영 대시보드 | 요청, worker, backup, health 상태를 확인한다. |

## 노트 종류

| 종류 | 의미 |
| --- | --- |
| `inbox` | 작성중 메모. 사용자가 처음 입력한 원문이다. |
| `archive` | AI 처리 뒤 보존되는 원문이다. 일반 목록에서는 `원문`으로 표시한다. |
| `source` | AI가 만든 핵심 결과 노트다. 사람이 읽는 `읽기용 정리`와 시스템이 활용하는 구조화 분석을 함께 담는다. |
| `topic` | 여러 source가 연결될 수 있는 주제 노트다. |
| `entity` | 사람, 회사, 종목, 제품, 장소 같은 대상 노트다. |
| `log` | 운영/피드백 기록이다. |
| `template` | 향후 템플릿 확장을 위한 종류다. |

## 처리 원칙

- 원문은 사용자의 실제 입력 근거로 보존한다.
- AI가 만든 결과는 바로 확정하지 않고 검토 가능한 제안으로 남긴다.
- 사람이 승인한 연결만 태그/주제/대상/일정으로 반영한다.
- 상대 날짜는 처리 기준 시각과 함께 절대 날짜 후보를 남긴다.
- 일정 후보는 `기록 전용`, `일정`, `할 일`, `마감`, `후속 확인`, `알림` 의도를 함께 남긴다.
- 이미 완료된 상태 기록은 도메인과 무관하게 `기록 전용`으로 남기고, 실제 미래 일정이나 후속 확인이 명시된 경우에만 일정/알림으로 등록한다.
- AI 재분석은 기존 원문, 현재 source, 열린 문서 피드백을 함께 사용한다.
- 노트 삭제 시 연결된 일정/알림은 취소되고, 고아 주제/대상은 재검토 또는 삭제된다.

## 대화형 검색 원칙

- 대화는 단순 문자열 검색이 아니라 구조화된 노트와 연결 정보를 함께 사용한다.
- “뭐야?”, “부족한 것은?”, “자세히 알려줘” 같은 일반 질문은 검색 결과를 그대로 나열하지 않고 결론을 먼저 작성한다.
- 근거 목록은 별도 패널이나 모바일 정보 화면에서 확인한다.
- AI 답변 제공자가 설정되어 있지 않으면 규칙 기반 답변으로 자동 전환한다.

## 보안 원칙

- 브라우저는 HttpOnly session cookie를 사용한다.
- admin token은 HTML, JavaScript, localStorage, sessionStorage에 저장하지 않는다.
- 외부 클라이언트 token과 admin token은 역할을 분리한다.
- 실제 credential은 서버 전용 `.env` 또는 secret file에 둔다.
