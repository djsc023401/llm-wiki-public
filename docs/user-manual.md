# 사용자 매뉴얼

이 문서는 `llm-wiki`를 처음 사용하는 사람을 위한 안내서다. 설치자는 [설치 매뉴얼](./setup-manual.md), 운영자는 [운영자 매뉴얼](./operator-manual.md)을 본다.

## llm-wiki가 하는 일

`llm-wiki`는 사용자가 남긴 자유 메모를 AI가 정리하고, 사용자가 그 결과를 검토해 개인 지식 저장소로 만들어 가는 웹 워크벤치다.

중요한 점:

- 기본 사용 화면은 `/notes` 웹 워크벤치이며, 첫 화면은 `홈` 요약이다.
- 제목은 비워도 된다. AI 처리 결과가 source note 제목을 제안한다.
- 태그, 주제, 대상은 직접 편집하지 않고 AI 제안과 승인으로 반영한다.
- 일정과 알림도 AI가 후보를 만들고 사람이 등록한다.

## 처음 시작하기

1. 운영자가 제공한 앱 URL을 연다. 예: `https://notes.example.com`
2. 로그인 화면에서 admin token 또는 운영자가 제공한 로그인 방식을 사용한다.
3. `홈`에서 우선 처리 항목, 미검토 제안, 활성 일정/할 일, 최근 노트, 작성중 노트를 확인한다.
4. 좌측 선택 상자에서 `노트`를 고른다.
5. `새 노트`를 눌러 메모를 작성한다.
6. 저장 상태가 `저장됨`인지 확인한다.
7. `AI로 처리`를 눌러 source note를 만든다.
8. 처리 완료 뒤 `결과 열기`로 생성된 source note를 확인한다.

source note의 `읽기용 정리`는 원문을 사람이 다시 읽기 쉬운 문장으로 풀어쓴 영역이다. `요약`, `추출된 사실`, `제안`은 검색과 AI 재분석을 위한 구조화된 영역으로 보면 된다.

## 홈 화면

`홈`은 개인 작업 요약 화면이다.

- 미검토 제안, 활성 일정/할 일, 실패한 AI 처리 요청, 최근 노트, 작성중 노트 수, 오래된 작성중 노트를 한 곳에서 확인한다.
- 알림 발송 이력은 별도 `알림` 화면에서 확인한다. 홈에서는 실패 알림처럼 사용자가 처리해야 하는 항목만 오늘 브리핑과 우선 처리 큐에 올린다.
- `지금 먼저 처리할 것`은 지연 항목, AI 처리 실패, 실패 알림, 오늘 일정/할 일, 미검토 제안, 오래된 작성중, 다가오는 일정/할 일 순서로 우선 처리할 항목을 모아 보여준다. 한 종류가 목록을 독점하지 않도록 각 종류의 대표 항목을 먼저 보여주고 남은 자리를 우선순위 순서로 채운다. 일정/할 일은 홈에서 바로 완료 또는 취소할 수 있고, 미검토 제안은 바로 승인 또는 거절할 수 있다.
- 상단의 `오늘 브리핑`은 오늘 처리할 일정/할 일, 지연된 항목, 설정한 일정 조회 범위 안의 예정 항목, AI 처리 실패, 실패 알림, 미검토 제안, 작성중 노트, 3일 이상 수정되지 않은 작성중 노트를 압축해서 보여준다. 마감일이나 시작일이 지난 항목은 알림 시간이 오늘이어도 지연 항목으로 우선 분류한다.
- 홈의 항목을 열면 기존 `제안`, `일정`, `알림`, `노트` 화면으로 이동해 바로 처리할 수 있다.
- `오래된 작성중`을 열면 노트 화면이 3일 이상 수정되지 않은 작성중 메모 목록으로 필터링된다.
- 홈 검색은 현재 홈에 표시된 항목 안에서 제목, 본문, 태그, 주제, 대상, 상태를 간단히 거른다.

## 노트 화면

좌측에는 보기 선택, 검색, 목록이 있다.

- `작성중`: 사용자가 작성한 원문 메모
- `오래된 작성중`: 기본 3일 이상 수정되지 않은 작성중 메모
- `소스`: AI가 만든 source note. 읽기용 정리와 구조화 분석이 함께 있다.
- `주제`: 승인된 주제 노트
- `대상`: 승인된 대상 노트
- `원문`: source note를 만들 때 보존한 원문
- `로그`: 운영 또는 피드백성 기록

가운데에는 Markdown 편집기와 미리보기가 있다.

- 작성중 메모는 기본으로 `작성` 화면이 열린다.
- 소스, 주제, 대상은 기본으로 `미리보기`가 열린다.
- `작성`, `미리보기`, `분할`을 직접 바꾸면 같은 노트 안에서 선택이 유지된다.

우측에는 선택한 노트의 작업 패널이 있다.

- `AI 작업`: 처리, 재분석, 결과 열기, 마크다운 내보내기
- `제안`: 태그, 주제, 대상, 일정 후보 검토
- `원문`: source note의 원문과 원문에 첨부했던 이미지/파일 확인
- `일정/알림`: 연결된 일정과 알림 확인
- `문서 피드백`: 정정 또는 추가 설명 저장과 재처리
- `첨부파일`: 현재 노트의 파일 업로드, 열기, 링크 삽입
- `수정 기록`: 이전 리비전 보기
- `노트 정보`: 내부 상태와 ID 확인

## 제안 승인

AI가 source note를 만들면 태그, 주제, 대상, 일정 후보를 제안할 수 있다.

- 태그 후보는 `적용`하면 현재 source note의 태그로 붙는다.
- 주제/대상 후보는 `승인`, `연결`, `승격` 같은 버튼으로 반영한다.
- 같은 slug의 주제/대상이 이미 있으면 새로 만들지 않고 기존 노트에 연결한다.
- 좌측 보기 선택에서 `제안`을 고르면 여러 노트의 미검토 제안을 한 번에 볼 수 있다.
- 제안 목록에서도 각 항목을 열지 않고 바로 승인/거절할 수 있다.
- 제안 목록에서 여러 항목을 체크한 뒤 `선택 승인` 또는 `선택 거절`로 한 번에 처리할 수 있다. 거절됨 필터에서는 체크한 항목을 한 번에 복원할 수 있다.

## 문서 피드백과 재분석

source note가 틀렸거나 최신 정보가 필요하면 `문서 피드백`에 내용을 남긴다.

```text
A가 2026년 7월 1일에 방문하기로 변경됨.
```

피드백을 저장한 뒤 `재처리`를 누르면 열린 피드백 전체가 AI 재분석에 반영된다. 이미 만들어진 source note도 `AI 재분석`으로 다시 처리할 수 있다.

source note가 재분석되면 그 source와 승인 연결된 주제/대상 노트의 연결 소스 요약도 함께 갱신된다. 따라서 같은 대상에 여러 메모가 연결된 경우, 재분석 뒤 대상 문서는 최신 source 내용과 연결 소스 수를 다시 반영한다.

## 일정과 알림

AI가 일정, 마감, 예약, 후속 확인을 찾으면 일정 후보를 만든다.

- 후보는 사람이 `등록`해야 실제 일정/알림이 된다.
- 일정 후보를 등록하거나 worker가 자동 등록할 때 별도 채널을 지정하지 않으면 `설정`의 선호 알림 채널을 사용한다. 사용할 수 없는 채널은 자동으로 제외된다.
- 예약 완료, 구매 완료, 결제 완료, 검진 완료처럼 이미 끝난 사실은 기본적으로 `기록 전용`으로 남고 일정/알림으로 등록되지 않는다.
- 완료 기록 안에 진료일, 방문 예정일, 여행 출발일, 체크인, 마감, 후속 확인처럼 앞으로 발생할 시점이 별도로 있으면 그 미래 항목만 일정/할 일/후속 확인 후보가 된다.
- 예약, 방문, 구매, 여행, 마감, 제출, 완료 기록은 원문에 나중에 확인해야 한다는 근거가 있거나 명시된 미래 날짜에서 검토 시점을 도출할 수 있을 때만 후속 확인 후보가 된다. 일반적인 후속 확인 날짜를 임의로 만들지는 않는다.
- 등록된 일정은 좌측 보기 선택의 `일정`에서 모아 본다.
- 알림 예정과 발송 이력은 `알림`에서 본다.
- `알림`의 `예정`은 아직 발송 delivery가 만들어지지 않은 활성 일정 기준이다. delivery가 만들어진 항목은 `대기`, `발송 중`, `발송됨`, `실패`, `취소` 상태 이력으로 표시되어 같은 항목이 중복으로 보이지 않게 한다.
- 활성 일정/알림은 상세 화면이나 노트의 `일정/알림` 패널에서 `완료`, `취소`, `1시간 미루기`, `내일 아침`으로 빠르게 처리할 수 있다.
- 모바일에서는 `일정`이나 `알림` 화면이 목록 탭으로 열리며, 항목을 선택하면 상세 화면에서 `목록으로` 버튼으로 바로 돌아갈 수 있다.
- 일정을 미루면 아직 발송되지 않은 연결 알림도 새 예정 시각으로 함께 갱신된다.
- PWA Push는 HTTPS와 브라우저 권한이 필요하다.
- Telegram은 운영자가 설정한 경우 보조 채널로만 사용한다.
- 상단 `설정`에서 운영 모드, 기본 시간대, 일정 조회 범위, 하루 요약 시간, 선호 알림 채널을 먼저 저장할 수 있다. 개인 용어, 분류 기준, 기록 전용 용어, 후속 확인 용어, 자주 등장하는 사람/장소/프로젝트/생활 카테고리, 별칭, 우선순위 용어, 사용자 분류 축, 답변 선호 규칙은 `고급 개인화 설정`을 펼쳐 조정한다.
- 설정 화면의 `개인 프로필 후보`는 활성 소스, 주제, 대상에서 추린 값이다. 필요한 후보를 체크해 `선택 추가`를 누르면 기존 개인 프로필 목록에 병합된다. 체크하지 않은 후보는 저장되지 않는다.
- 운영 모드는 `범용`과 `개인 운영` 중 선택한다. `개인 운영`은 AI가 같은 근거를 사용하되 답변, 일정, 후속 확인을 개인 비서 흐름에 맞춰 정리하도록 돕는다.
- 같은 화면에서 알림 채널 상태와 테스트 발송 결과를 확인할 수 있다.
- 설정 화면은 입력 기준, 해석 방식, 입력 금지 항목을 함께 보여준다. 반복해서 등장하는 표현만 입력하고, 토큰, 비밀번호, 내부 주소, 로컬 경로, 실제 자격 증명은 입력하지 않는다.
- 저장한 개인 용어, 분류 기준, 기록 전용 용어, 후속 확인 용어, 개인 프로필, 별칭, 우선순위 용어, 사용자 분류 축, 답변 선호 규칙은 이후 AI 처리와 재분석에서 해석 힌트로 사용된다. 기록 전용 용어는 완료된 사실이 불필요한 일정/알림으로 자동 등록되는 일을 줄이고, 후속 확인 용어는 원문 근거가 있을 때 확인 후보를 잡는 데 쓴다. 별칭은 원문에 등장한 다른 표현을 알아보는 데 쓰고, 우선순위 용어와 사용자 분류 축은 근거가 있는 후보의 순위와 정리 방식을 보정한다. 답변 선호 규칙은 대화 답변 형식에만 쓰인다. 개인화 값만으로 보유, 방문, 관계, 일정, 알림, 완료 사실을 만들지는 않는다. 원문과 피드백이 우선이며, 관련 없는 개인화 값은 강제로 적용하지 않는다.
- 기록 전용/후속 확인 용어는 `예약 완료`, `확인 필요`처럼 구체적으로 적는다. `완료`, `필요`, `확인`처럼 너무 넓은 단어는 저장 경계에서 제외되며, AI가 명시적으로 `할 일`, `마감`, `후속 확인`으로 분류한 후보는 기록 전용 용어만으로 숨기지 않는다.
- Telegram이 연결되어 있으면 `/note <내용>` 또는 `/capture <내용>`으로 빠른 메모를 작성중에 저장하고 AI 처리를 요청할 수 있다.
- `/chat <질문>` 또는 `/ask <질문>`으로 노트, 일정, 알림에 질문할 수 있다. Telegram 질문은 전용 대화 세션에 저장되어 후속 질문에서 이전 맥락을 이어받는다.
- `/today`, `/suggestions`, `/approve <id>`, `/reject <id>`, `/schedule`, `/notifications` 명령으로 오늘 브리핑, 제안, 일정/알림을 확인할 수 있다. `/today`는 웹 홈과 같은 기준으로 기준 날짜, 시간대, 조회 범위, 하루 요약 시간을 표시하고, `지금 먼저 처리할 것`을 상단에 보여준다. Telegram 버튼이 보이면 오늘 브리핑에서 일정/할 일을 바로 완료 또는 취소하고, 미검토 제안을 바로 승인 또는 거절하며, 실패 알림을 바로 취소 또는 삭제할 수 있다. 실패한 AI 처리 요청과 3일 이상 수정되지 않은 작성중 노트도 별도 항목으로 보여준다.
- `/today`, `/schedule`, `/notifications`의 예정 일정 범위는 설정의 `일정 조회 범위`를 따른다.
- `/suggestions` 응답에는 모바일에서 바로 누를 수 있는 승인/거절 버튼이 함께 표시된다. `/schedule`은 완료, 취소, 1시간 미루기, 내일 아침 버튼을 제공하고, `/notifications`는 예정 일정 처리와 알림 취소/삭제 버튼을 제공한다.
- 버튼이 보이지 않는 클라이언트에서는 목록의 짧은 ID를 사용한다. 제안은 `/approve <id>` 또는 `/reject <id>`, 일정/할 일은 `/done <id>`, `/cancel-time <id>`, `/snooze1 <id>`, `/tomorrow <id>`, 알림은 `/cancel-notification <id>`, `/delete-notification <id>`를 입력한다.

## 대화형 검색

좌측 보기 선택에서 `대화`를 고르면 자연어로 질문할 수 있다.

- 질문은 노트, 원문, 주제, 대상, 일정, 알림을 함께 검색한다.
- 같은 대화에서 추가 질문을 하면 이전 질문과 답변 맥락이 반영된다.
- 대화 이력은 App DB에 저장되므로 새로고침 뒤에도 유지된다. 브라우저에는 마지막으로 선택한 대화 ID만 보관한다.
- 대화는 설정의 기본 시간대와 일정 조회 범위를 사용해 상대 날짜와 `남은 일정` 같은 질문을 해석한다.
- `오늘 처리할 일`, `오늘 할 일`, `오늘 브리핑`처럼 물으면 웹 홈과 Telegram `/today`와 같은 기준으로 오늘 일정/할 일, 지연 항목, 설정 범위 안의 예정 항목, AI 처리 실패, 실패 알림, 미검토 제안, 작성중/오래된 작성중 노트를 함께 모아 답한다.
- 개인 용어, 분류 기준, 기록 전용/후속 확인 용어, 개인 프로필, 별칭, 우선순위 용어, 사용자 분류 축, 답변 선호 규칙은 답변 해석 힌트로만 쓰이며, 실제 근거가 없으면 사실로 단정하지 않는다.
- 개인 운영 모드에서는 개인 용어, 생활 카테고리, 별칭, 우선순위 용어, 사용자 분류 축이 실제 근거와 함께 맞는 결과의 순위를 약하게 보정할 수 있다. 이 보정은 후보를 새로 만들지 않으며, 보유, 예약, 방문, 완료 같은 사실은 원문이나 피드백 근거가 있어야 한다. 답변 선호 규칙은 검색 순위가 아니라 답변 표현에만 영향을 준다.
- `새 대화`는 독립 주제로 새 질문을 시작할 때 사용한다.
- `삭제`는 저장된 대화 세션을 화면과 일반 조회에서 숨긴다. 운영자가 별도 정리 명령을 실행하기 전까지는 DB와 백업에 남을 수 있다.
- 답변 아래의 `근거 N건` 버튼으로 근거 목록을 확인한다.
- 제목 링크를 누르면 관련 노트, 일정, 알림 상세로 이동한다.

## 노트 삭제

노트를 삭제하면 기본 목록에서 사라진다.

- 연결된 활성 일정은 자동으로 취소된다.
- 아직 발송되지 않은 연결 알림도 취소된다.
- 삭제한 source와 연결된 주제/대상은 남은 source가 있으면 재검토된다.
- 남은 source가 없으면 고아 주제/대상은 삭제될 수 있다.
- source만 삭제하고 원문을 남기면 고아 원문은 다시 `작성중`으로 돌아간다.
