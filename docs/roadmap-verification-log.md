# 로드맵 검증 요약

이 문서는 public 저장소에 남길 수 있는 검증 요약만 포함한다. 실제 서버 경로, 요청 ID, PR URL, 개인 도메인, 백업 파일명, 운영 로그는 private notes에 기록한다.

## 검증 원칙

- 공개 문서에는 결과와 범위만 남긴다.
- 민감한 운영 정보와 실사용 데이터는 남기지 않는다.
- 재현 가능한 검증 명령은 예시값으로 작성한다.

## 검증된 영역

| 영역 | 상태 | 공개 요약 |
| --- | --- | --- |
| API/worker 배포 | 검증됨 | Docker Compose 기반 API와 worker가 health check를 통과했다. |
| DB schema | 검증됨 | notes, revisions, links, assets, requests, feedback, time/notification tables가 migration으로 관리된다. |
| 웹 워크벤치 | 검증됨 | `/notes`에서 작성, 저장, AI 처리, 제안 검토, 첨부, 수정 기록 확인이 가능하다. |
| AI 처리 | 검증됨 | 작성중 메모를 source note로 만들고, source note 재분석을 수행한다. |
| 제안 | 검증됨 | 태그, 주제, 대상, 일정 후보를 검토하고 승인/거절할 수 있다. |
| 일정/알림 | 검증됨 | 등록된 일정과 알림 발송 이력을 목록/상세 구조로 확인한다. |
| 대화형 검색 | 검증됨 | 자연어 질문으로 노트와 일정/알림을 함께 검색하고 근거를 확인한다. |
| 백업/복구 | 검증됨 | DB dump, Git bundle, object archive, restore smoke 절차가 있다. |
| 보안 | 검증됨 | 웹 HTML에 token 값이 노출되지 않도록 테스트한다. |

## 개인화 로드맵 검증

| 단계 | 상태 | 공개 요약 |
| --- | --- | --- |
| W1 작업 기준점 | 검증됨 | 범용 기준선은 별도 branch/tag로 보존하고, 개인 운영 branch는 DB-first 서버 배포 흐름으로 유지한다. |
| W2 개인 프로필 | 검증됨 | 운영 모드, 기본 시간대, 일정 조회 범위, 하루 요약 시간, 기본 미리 알림, 선호 알림 채널, 개인 용어, 분류 기준, 기록 전용/후속 확인 용어, 개인 프로필 목록을 DB 설정으로 관리한다. 활성 소스, 주제, 대상 노트에서 사람, 장소, 프로젝트, 생활 카테고리 후보를 제안하되 자동 반영하지 않고, 사용자가 선택한 후보만 기존 설정에 병합한다. |
| W3 AI 분석 개인화 | 검증됨 | AI runner prompt와 일정 후보 parser는 기록 전용, 일정, 할 일, 마감, 후속 확인, 알림 의도를 구분하고, 완료 기록과 미래 행동을 분리한다. |
| W4 주제/대상 종합화 | 검증됨 | source 재분석 뒤 직접 연결된 주제/대상은 갱신된다. 여러 source가 연결된 주제/대상은 공통 맥락, 소스별 차이, 최근 기준 소스를 종합 정리에 표시한다. |
| W5 대화 품질 개인화 | 검증됨 | 대화형 검색은 이전 대화 맥락, 개인화 힌트, 근거 분리, 중복 제거, 관련 항목 링크를 지원하며 OpenAI 답변 provider가 꺼져도 규칙 기반 fallback을 사용한다. |
| W6 Telegram과 홈 개인 비서 | 검증됨 | 홈과 Telegram `/today`는 같은 오늘 브리핑 기준을 공유하고, Telegram은 `/note`/`/capture` 빠른 메모, `/chat`/`/ask` 대화형 질문, `/suggestions`, `/schedule`, `/notifications` 명령과 주요 callback 버튼을 제공한다. |
| W7 일정/알림 정책 | 검증됨 | 완료된 기록은 기본적으로 일정/알림 등록에서 제외하고, 명시 미래 일정과 기본 미리 알림, 알림 갱신/취소/삭제 흐름을 지원한다. |
| W8 공개 배포 준비 | 검증됨 | 공개 snapshot 정책, 점검표, 발행 절차 문서를 유지한다. 공개 demo seed는 합성 데이터로 샘플 노트, 제안, 일정 흐름을 만들 수 있으며, 전용 test DB의 demo seed smoke와 전체 테스트, 실제 운영 문자열 custom term 기반 공개 스캔을 통과했다. |

## 반복 발행 전 확인

공개 snapshot을 새로 발행할 때마다 다음 항목을 다시 확인한다.

- secret scanner 실행 또는 명시적 skip 사유 기록
- demo seed smoke 또는 `tests/test_demo_seed.py` 실행
- 실제 도메인/IP/경로 문자열 custom term 검색
- Markdown 링크 점검
- 전체 테스트 실행
