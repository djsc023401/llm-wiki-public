# 개인 운영 전환 계획

이 문서는 `llm-wiki`를 범용 개인 지식 서비스로 유지하면서, 실제 개인 메모와 일정 관리에 맞게 발전시키기 위한 실행 계획을 정리한다.

## 현재 방향

현재 개발 방향은 두 갈래를 동시에 유지한다.

- 범용 기준선: 공개 저장소와 새로운 사용자가 재사용할 수 있는 기본 제품이다.
- 개인 운영선: 실제 개인 메모, 일정, 알림, Telegram 보조 채널을 빠르게 개선하는 운영 제품이다.

범용 기준선은 `generic/base-2026-06-13` 브랜치와 `generic-base-2026-06-13` 태그로 보존한다. 개인 운영 개발은 별도 요청이 없다면 `master`에서 계속 진행한다.

이 문서의 단계는 Codex 목표 모드에서 하나씩 요청할 수 있는 크기로 나눈다. 각 단계는 구현, 테스트, 서버 반영, private notes 갱신까지 포함해야 완료로 본다.

## 기본 원칙

- 범용 기준선은 별도 브랜치와 태그로 보존한다.
- 개인화는 가능한 한 DB 설정, 운영 `.env`, private notes, 사용자 데이터로 관리한다.
- 앱 코어에는 특정 사용자, 특정 도메인, 특정 생활 패턴을 하드코딩하지 않는다.
- 공개 저장소에는 기능, schema, 예시 설정, 테스트, 공개 문서만 둔다.
- 실제 token, 내부 주소, 개인 메모, 운영 로그, 백업 산출물은 커밋하지 않는다.
- 개인 용어, 자주 등장하는 사람/장소/프로젝트, 생활 패턴은 secret이 아니어도 개인 운영 데이터로 취급한다.
- 개인 운영에서 발견한 불편은 먼저 범용 정책으로 추상화할 수 있는지 검토한다.
- 범용 정책으로 표현할 수 없는 값은 개인 설정 또는 실제 데이터로만 둔다.

## 개인화 경계

| 영역 | 공개 코어에 둘 내용 | 개인 운영에 둘 내용 |
| --- | --- | --- |
| 설정 | 개인화 설정 schema, API, UI | 실제 기본 시간대, 용어, 분류 기준, 별칭, 우선순위, 답변 선호 |
| AI 분석 | 개인화 context를 받는 공통 prompt 구조 | 개인 용어, 기록 전용/후속 확인 용어, 자주 쓰는 장소/사람/프로젝트, 운영 힌트 |
| 대화 | 근거 기반 질의응답 구조, fallback 정책 | 사용자의 실제 노트와 일정 |
| 일정/알림 | 일정/알림 모델과 보수적 등록 정책 | 선호 알림 채널, 기본 미리 알림 시간 |
| Telegram | 명령 처리, 버튼, 권한 검증 | bot token, chat id, 개인 명령 사용 패턴 |
| 백업 | 백업/복구 절차와 검증 도구 | 실제 dump, object archive, restore 로그 |

## 운영 모드

개인화 설정에는 `workflow_mode`가 있다.

- `generic`: 공개 저장소와 범용 사용자를 위한 기본값이다. AI는 중립적인 지식 워크벤치 관점으로 메모를 정리한다.
- `personal`: 개인 서버에서 선택하는 운영 모드다. AI는 원문과 피드백 근거를 유지하면서 일정, 할 일, 후속 확인, 오늘 처리할 항목을 개인 비서 흐름에 맞춰 정리한다.

빈 DB에서는 `APP_DEFAULT_WORKFLOW_MODE` 환경변수가 초기 운영 모드를 정한다. 공개 배포 템플릿은 `generic`을 기본으로 두고, 개인 운영 서버는 `personal`로 바꿀 수 있다. 설정 화면에서 한 번 저장하면 DB의 `personalization_settings` 값이 환경변수보다 우선한다.

운영 모드는 사실 근거가 아니다. 따라서 `personal`이어도 원문, 승인된 연결, 사용자 피드백 없이 일정/알림/주제/대상을 만들어서는 안 된다.

## 실행 순서 요약

| 단계 | 목표 | 주요 산출물 |
| --- | --- | --- |
| W1 | 기준선과 공개/개인 경계 정리 | 브랜치 정책, 공개 점검, private notes 기록 |
| W2 | 개인 설정 입력 품질 개선 | 설정 화면, 개인 프로필, 힌트 whitelist |
| W3 | 메모 분석 개인화 | 읽기 쉬운 소스 노트, 완료/미래 행동 분리 |
| W4 | 주제/대상 종합화 | 여러 소스를 반영한 주제/대상 요약 |
| W5 | 대화형 답변 품질 개선 | 결론 우선 답변, 근거 분리, 후속 질문 맥락 |
| W6 | Telegram과 홈 개인 비서화 | 버튼 중심 명령, 오늘 브리핑, 모바일 처리 |
| W7 | 일정/알림 정책 정교화 | 불필요한 알림 억제, 취소/삭제/미루기 |
| W8 | 공개 배포 준비 | demo seed 구현/검증, scanner, 공개 snapshot 검증 |

## W1. 기준선과 공개/개인 경계 정리

목표는 개인 운영 개발을 시작하기 전 기준 상태를 안전하게 고정하는 것이다.

작업:

- `generic/base-2026-06-13` 브랜치와 `generic-base-2026-06-13` 태그가 존재하는지 확인한다.
- `master`를 개인 운영 live 브랜치로 사용하는 정책을 문서화한다.
- 공개 저장소 발행 문서가 snapshot-only 정책을 설명하는지 확인한다.
- `agent_private.md`, `.env`, key, 백업, 실제 메모 데이터가 추적되지 않는지 확인한다.
- 개인화 설정의 실제 값이 공개 문서, Git diff, 이슈, runner 로그 예시에 들어가지 않는지 확인한다.
- 개인 운영 서버의 현재 배포 커밋과 health를 private notes에 기록한다.

완료 기준:

- `git status --short --branch` 결과가 의도한 변경만 보여준다.
- 공개 문서에는 실제 도메인, 내부 IP, token 본문, 개인 메모가 없다.
- 서버 source checkout이 최신 커밋으로 갱신되어 있다.
- 다음 단계가 개인 설정 개선으로 바로 이어질 수 있다.

## W2. 개인 설정 입력 품질 개선

목표는 AI가 개인 메모를 해석할 때 참고할 수 있는 기본값을 사용자가 안전하게 관리하도록 만드는 것이다.

작업:

- 설정 화면에서 운영 모드, 시간대, 일정 조회 범위, 하루 요약 시간, 기본 미리 알림을 관리한다.
- 개인 용어, 분류 기준, 기록 전용 용어, 후속 확인 용어를 입력할 수 있게 한다.
- 자주 등장하는 사람, 장소, 진행 중인 프로젝트, 생활 카테고리를 개인 프로필로 저장한다.
- 별칭, 우선순위 용어, 사용자 분류 축, 답변 선호 규칙을 운영 힌트로 저장한다.
- 저장 경계에서 `metadata.workflow_mode`, `metadata.profile`, `metadata.hints`만 허용한다.
- token, 내부 주소, 운영 식별자 같은 secret-like 값은 개인화 설정과 AI context에 들어가지 않게 한다.
- 설정 화면에는 “근거가 아니라 해석 힌트”라는 의미가 드러나야 한다.

완료 기준:

- `GET /api/personalization`과 `PUT /api/personalization`이 같은 schema를 다룬다.
- partial update 후 기존 프로필 목록과 운영 힌트 목록이 유지된다.
- AI runner prompt에는 whitelist된 개인화 힌트만 전달된다.
- 설정값만으로 일정, 알림, 주제, 대상을 새로 만들지 않는다.

## W3. 메모 분석 개인화

목표는 자유 메모를 개인 생활에 맞게 더 잘 구조화하는 것이다.

- 예약 완료, 구매 필요, 병원 방문, 가족 일정, 투자 관찰 같은 표현을 더 정확히 분류한다.
- 설정한 기록 전용 용어는 완료 사실을 일정/알림으로 자동 등록하지 않는 힌트로 사용한다.
- 설정한 후속 확인 용어는 원문 근거가 있을 때만 후속 확인 후보를 만드는 힌트로 사용한다.
- 완료된 사실은 알림으로 만들지 않고 기록으로 남긴다.
- 미래 일정, 마감, 후속 확인, 할 일은 검토 가능한 후보로 만든다.
- 원문 근거와 사용자 피드백을 개인화 힌트보다 우선한다.
- 완료 기록과 미래 행동을 분리하는 규칙은 특정 병원/예약 사례가 아니라 모든 도메인에 적용한다.
- `알림 필요 없음`, `등록할 일정이 아님`, `후속 확인 필요 없음` 같은 부정 문맥은 미래 행동으로 해석하지 않는다.

완료 기준:

- 동일한 표현이 기록 전용/일정/알림으로 잘못 분류되는 사례가 줄어든다.
- 분석 결과는 사람이 읽기 쉬운 정리와 구조화 정보를 함께 가진다.
- 태그/주제/대상은 직접 확정하지 않고 제안과 승인 흐름을 유지한다.

## W4. 주제/대상 종합화

목표는 주제와 대상 노트가 단순 출처 목록이 아니라 연결된 소스를 종합한 문서가 되도록 하는 것이다.

- 주제/대상은 승인된 연결과 원문 근거를 기준으로 요약한다.
- 여러 소스가 연결되면 공통점, 차이, 최근 변경 사항을 분리해 정리한다.
- 연결된 소스가 재분석되면 연결된 주제/대상 본문도 해당 source의 최신 읽기용 정리와 요약을 반영한다.
- 연결된 소스가 삭제되면 남은 source가 있는 주제/대상은 재검토 대상으로 표시한다.
- 연결된 소스가 없어진 주제/대상은 자동 삭제 후보로 표시한다.
- 주제/대상 본문에 내부 ID를 노출해야 할 때는 미리보기에서 제목 링크로 대체한다.

완료 기준:

- 주제/대상 노트에서 연결된 소스 개수와 근거를 확인할 수 있다.
- 같은 대상에 여러 소스가 연결되면 본문 요약이 하나의 소스에만 치우치지 않는다.
- 삭제 또는 재분석 후 연결 상태가 UI와 본문에서 일치한다.

## W5. 대화 품질 개인화

목표는 대화가 단순 검색 결과 나열이 아니라 사용자의 질문에 답하는 형태가 되도록 하는 것이다.

- “내가 가진 것”, “예약한 것”, “투자 중인 것”, “해야 할 일” 같은 상태 질문은 명시 근거가 있을 때만 답한다.
- 근거가 부족하면 단정하지 않고 부족한 근거를 설명한다.
- 개인 용어, 분류 기준, 개인 프로필, 별칭, 우선순위 용어, 사용자 분류 축은 후보 생성 조건이 아니라 근거가 있는 후보의 `score_only` 순위 보정과 답변 표현 힌트로만 사용한다. 답변 선호 규칙은 검색 순위가 아니라 답변 형식과 검토 우선순위 힌트로만 사용한다.
- 후속 질문은 이전 대화의 의도와 근거를 이어받는다.
- 대화 세션과 turn은 App DB에 저장해 새로고침과 기기 전환 뒤에도 이어진다.
- 근거는 본문 답변과 분리해 필요할 때 볼 수 있게 유지한다.
- `오늘 처리할 일` 계열 질문은 홈/Telegram 오늘 브리핑과 같은 기준으로 일정, 지연 항목, 예정 항목, AI 처리 실패, 실패 알림, 미검토 제안, 작성중/오래된 작성중을 함께 답한다.

완료 기준:

- 답변은 결론을 먼저 제시한다.
- 중복 근거가 줄어든다.
- 관련 노트, 일정, 알림으로 이동할 수 있다.
- 저장된 세션 ID만으로 후속 질문 맥락을 복원할 수 있다.
- OpenAI API provider가 꺼져 있어도 규칙 기반 답변이 안전하게 동작한다.

## W6. Telegram과 홈 개인 비서화

목표는 모바일과 첫 화면에서 빠르게 처리해야 하는 항목을 같은 기준으로 다룰 수 있게 하는 것이다.

- `/today`는 오늘 할 일, 일정, 지연 항목, AI 처리 실패, 미검토 제안을 요약한다.
- `/suggestions`는 승인/거절 버튼을 우선 제공한다.
- 버튼 라벨은 모바일에서 목록 번호와 동작이 바로 보이도록 구성하고, 버튼이 불가능한 경우 짧은 ID 명령을 유지한다.
- `/schedule`과 `/notifications`는 남은 일정과 알림 상태를 짧게 보여주고, 일정 완료/취소/미루기와 알림 취소/삭제 버튼을 제공한다.
- 버튼이 불가능한 클라이언트에서는 짧은 ID 명령을 대체 경로로 둔다.
- 홈은 오늘 할 일, 곧 다가오는 일정, AI 처리 실패, 미검토 제안, 최근 노트, 오래 방치된 작성중 메모를 보여주고, 별도 `지금 먼저 처리할 것` 큐에서는 지연 항목, AI 처리 실패, 실패 알림, 오늘 일정/할 일, 미검토 제안, 오래된 작성중, 다가오는 일정/할 일 순으로 압축한다. 알림 발송 이력은 별도 알림 화면에 두며, 홈에는 사용자가 처리해야 하는 실패 알림만 노출한다.
- 대화의 `오늘 처리할 일` 답변도 홈과 Telegram `/today`가 쓰는 오늘 브리핑 기준을 공유한다.

완료 기준:

- Telegram 응답은 모바일에서 바로 누를 수 있는 형태다.
- 허용 chat만 명령을 처리한다.
- token과 chat id는 UI, 로그, 문서에 노출되지 않는다.
- 홈, Telegram `/today`, 대화의 `오늘 처리할 일` 답변이 같은 오늘 브리핑 기준을 공유한다.
- 홈 항목은 원래 상세 화면으로 이동할 수 있고 모바일에서도 같은 우선순위로 볼 수 있다.

## W7. 일정/알림 정책 정교화

목표는 개인 일정 관리에서 불필요한 알림을 줄이고, 필요한 후속 조치를 놓치지 않게 하는 것이다.

- 완료된 사실과 미래 행동을 명확히 구분한다.
- 개인 기본 미리 알림 시간을 설정하고, AI 후보에 명시 알림이 없을 때만 시작/마감 시각 기준으로 보강한다.
- 예약, 병원, 구매, 여행, 마감 같은 항목에 기본 후속 확인 후보를 제안한다.
- 이미 발송된 알림과 앞으로 발송될 알림을 UI에서 구분한다.
- 일정 변경 시 연결된 미발송 알림을 함께 갱신한다.

완료 기준:

- 완료된 기록이 불필요한 미래 알림으로 생성되지 않는다.
- 명시 알림 시간이 없는 미래 일정은 개인 기본값에 따라 미리 알림을 만들 수 있다.
- 사용자가 알림을 취소, 삭제, 미루기 할 수 있다.
- 알림 실패 원인을 운영 화면에서 확인할 수 있다.

## W8. 공개 배포 준비

목표는 개인 운영 흐름을 유지하면서 공개 배포 가능한 snapshot을 만들 수 있게 하는 것이다.

- 공개용 demo seed와 예시 데이터는 실제 개인 메모와 분리한다.
- 공개 snapshot에는 현재 추적 파일만 포함하고, 전체 개발 히스토리는 복사하지 않는다.
- public 발행 전 scanner, 실제 도메인/IP/개인 경로 검색, 문서 링크 점검을 수행한다.
- demo seed는 합성 원문, source, 주제/대상, 제안, 일정 샘플을 만들고 재실행 시 중복 생성하지 않는다.

완료 기준:

- 공개 저장소 발행 절차가 현재 구현과 일치한다.
- 공개 문서와 demo seed에는 개인 운영 데이터가 없다.
- 전용 test DB에서 demo seed smoke가 통과한다.

## 검증 기준

개인 운영 전환 작업은 다음 기준을 통과해야 한다.

- 관련 단위 테스트 또는 API 테스트가 있다.
- 서버 컨테이너에서 테스트를 실행한다.
- 배포 뒤 `/health`가 정상이다.
- 개인 정보와 secret이 공개 문서나 Git diff에 포함되지 않는다.
- 특정 사용자에게만 맞는 규칙은 코드가 아니라 설정/데이터로 표현한다.
