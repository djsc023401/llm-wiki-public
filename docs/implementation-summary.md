# 구현 요약

이 문서는 공개 가능한 수준의 구현 상태를 요약한다. 세부 운영 로그와 실제 배포 기록은 private notes에 둔다.

## 구현된 핵심

- FastAPI 기반 API 서버와 `/notes` 웹 워크벤치
- Postgres 기반 노트, 리비전, 링크, 첨부, 제안, 일정, 알림, 요청 저장소
- Raw SQL 기반 repository 함수. ORM은 사용하지 않는다.
- Worker loop와 AI runner abstraction
- Codex CLI runner와 선택적 OpenAI API 답변 계층
- Markdown mirror export
- MinIO/S3 호환 첨부 저장
- PWA Push 알림과 선택적 Telegram 보조 채널
- Telegram `/note`/`/capture` 빠른 메모, `/chat`/`/ask` 대화형 질문, `/today` 오늘 브리핑
- 선택적 하루 요약 자동 발송. `DAILY_DIGEST_ENABLED=true`이면 worker가 개인화 설정의 하루 요약 시간 이후 `/today`와 같은 브리핑을 기본 알림 채널로 하루 한 번 보낸다.
- 운영 대시보드와 health check. 대시보드는 처리 요청 실패를 runner, 입력 방식, 출처, 실패 원인별로 묶어 보여준다.
- 백업, restore smoke, object archive 검증
- 공개 설치자가 샘플 노트, 제안, 일정 흐름을 확인할 수 있는 선택적 demo seed

## 웹 워크벤치

웹 워크벤치는 다음 보기를 제공한다.

- 홈
- 노트
- 제안
- 일정
- 알림
- 대화

홈은 미검토 제안, 활성 일정/할 일, 실패한 AI 처리 요청, 최근 노트, 작성중 노트 수, 오래된 작성중 노트를 모아 보여주는 개인 작업 요약 화면이다. 알림 발송 이력은 별도 알림 화면에 두고, 홈에는 실패 알림처럼 사용자가 처리해야 하는 항목만 오늘 브리핑과 우선 처리 큐에 올린다. `지금 먼저 처리할 것`은 같은 오늘 브리핑 빌더에서 만든 우선 처리 큐를 사용해 지연 항목, AI 처리 실패, 실패 알림, 오늘 일정/할 일, 미검토 제안, 오래된 작성중, 다가오는 일정/할 일 순서로 압축해 보여준다. 우선 처리 큐는 각 버킷의 대표 항목을 먼저 배치한 뒤 남은 자리를 버킷 우선순위대로 채워 한 종류가 목록을 독점하지 않게 한다. 홈의 우선 처리 카드에서는 활성 일정/할 일을 바로 완료 또는 취소할 수 있고, 미검토 제안을 바로 승인 또는 거절할 수 있다. `오늘 브리핑`은 개인 시간대 기준으로 오늘 일정/할 일, 지연 항목, 개인화 설정의 일정 조회 범위 안에 있는 예정 항목, AI 처리 실패, 실패 알림, 미검토 제안, 작성중 노트, 3일 이상 수정되지 않은 작성중 노트를 압축해 보여주며 화면 메타에 적용 중인 시간대를 함께 표시한다. 마감일이나 시작일이 지난 일정/할 일은 알림 시간이 오늘이어도 지연 항목으로 우선 분류한다. 홈, Telegram `/today`, 선택적 daily digest는 공통 브리핑 빌더를 사용하고, Telegram과 daily digest 본문은 같은 텍스트 포맷터를 공유한다. 대화의 `오늘 처리할 일` 답변도 같은 버킷 우선순위로 표시한다. Telegram 본문도 기준 날짜, 시간대, 조회 범위, 하루 요약 시간을 먼저 표시하고 `지금 먼저 처리할 것` 버튼으로 일정/할 일 완료 또는 취소, 미검토 제안 승인 또는 거절, 실패 알림 취소 또는 삭제를 처리할 수 있다. 오래된 작성중 노트는 일반 작성중 목록에서 중복 표시하지 않는다. 같은 소스에서 나온 일정과 준비 마감처럼 관련된 시간 항목은 대표 일정 하나에 관련 항목 수를 붙여 보여준다. Telegram `/note`와 `/capture`는 모바일에서 빠르게 원문 메모를 작성중으로 저장하고 AI 처리 요청을 큐에 넣는다. Telegram `/chat`과 `/ask`는 공통 채팅 서비스 계층을 통해 전용 대화 세션을 저장해 후속 질문 맥락을 유지한다. 홈의 오래된 작성중 항목은 노트 화면의 전용 필터와 연결된다.

노트 상세에는 Markdown 작성/미리보기/분할, AI 작업, 원문, 제안, 일정/알림, 문서 피드백, 첨부파일, 수정 기록, 노트 정보 패널이 있다. 활성 일정/알림은 노트 패널과 일정/알림 상세에서 완료, 취소, 1시간 미루기, 내일 아침 미루기를 바로 처리할 수 있으며 발송 전 알림은 변경된 시간으로 같이 갱신된다. 모바일 일정/알림 화면은 목록에서 항목을 고른 뒤 상세 안의 `목록으로` 버튼으로 바로 돌아갈 수 있게 구성한다.

## AI 처리

- 작성중 메모를 source note로 변환한다.
- source note를 원문과 피드백 기준으로 재분석한다.
- 개인화 설정의 운영 모드를 AI context에 전달해 범용 워크벤치 또는 개인 운영 흐름 중 어느 관점으로 정리할지 알려준다.
- 개인화 metadata는 `workflow_mode`, profile 목록, 운영 힌트 목록만 보존하며, 임의 key는 저장/조회 경계에서 제거한다.
- 기록 전용 용어와 후속 확인 용어는 AI 분석과 대화에서 해석 힌트로 전달되며, 완료 사실이 불필요한 일정/알림으로 자동 등록되는 일을 줄인다.
- 태그/주제/대상/일정 후보를 생성한다.
- 전역 제안 목록에서 여러 후보를 선택해 일괄 승인, 거절, 복원할 수 있다.
- 일정 후보 등록은 개인화 설정의 선호 알림 채널과 실제 사용 가능한 채널을 교차해 기본 채널을 정한다.
- 미래 일정 자체는 유효하지만 원문이나 검토 메모가 알림이 필요 없다고 명시하면, 일정은 등록하되 알림 채널은 비워 두어 발송 대기열을 만들지 않는다.
- 일정 후보의 근거가 개인화 참고나 비근거 힌트뿐이면 worker 자동 등록 대상에서 제외한다.
- 승인된 연결을 DB에 저장하고 필요 시 Markdown mirror에 반영한다.
- AI 처리 회귀 테스트는 Codex CLI/OpenAI API runner 프롬프트와 재분석 임시 노트에서 개인화 설정이 비근거 해석 힌트로만 전달되는지 확인한다.

## 대화형 검색

- 검색 대상은 source, topic, entity, 원문, 일정, 알림이다.
- 질문 의도에 따라 일정 중심, 상태 중심, 설명 중심 답변을 만든다.
- `오늘 처리할 일` 계열 질문은 홈과 Telegram `/today`가 쓰는 오늘 브리핑 기준을 공유한다. 오늘 일정/할 일, 지연 항목, 개인화 설정 범위 안의 예정 항목, AI 처리 실패, 실패 알림, 미검토 제안, 작성중/오래된 작성중 노트를 같은 우선순위로 묶어 답한다.
- 개인화 설정의 기본 시간대와 일정 조회 범위를 사용해 상대 날짜와 열린 미래 범위를 해석한다.
- 근거 항목은 별도 패널에서 확인할 수 있다.
- 답변 본문에 등장하는 관련 노트, 소스, 원문 제목은 가능한 경우 상세 화면으로 이동할 수 있는 링크로 표시한다.
- OpenAI API provider가 설정되면 결정적 로직이 고른 근거를 바탕으로 자연어 답변을 생성한다.
- OpenAI API 답변 provider에는 개인 용어, 분류 기준, 기록 전용/후속 확인 용어, 개인 프로필, 별칭, 우선순위 용어, 사용자 분류 축, 답변 선호 규칙이 힌트로 전달되지만 근거로 단독 사용하지 않는다.
- OpenAI API 답변 provider는 근거 수, prompt 크기, 출력 token 상한을 두며, prompt가 상한을 넘으면 API를 호출하지 않고 규칙 기반 답변으로 전환한다.
- OpenAI API 답변 provider의 모델, prompt 크기, 근거 수, token 사용량, 예상 비용, fallback 사유는 대화 turn metadata에 저장되어 이후 품질과 비용을 점검할 수 있다. 비용 추정은 운영자가 입력/출력 100만 token당 단가를 설정한 경우에만 계산한다.
- 대화 세션 삭제는 먼저 soft delete로 일반 조회에서 숨긴다. 운영자는 `llm-wiki chat-cleanup --deleted-retention-days N`으로 삭제된 세션과 turn을 hard purge할 수 있으며, 대화 이력은 purge 전까지 App DB 백업에 포함된다.
- 운영자는 `llm-wiki data-lifecycle-report`로 노트, 노트 첨부, 처리 요청 첨부, 대화 이력, 알림 이력, 하루 요약 이력, 백업 범위와 정리 권장 항목을 읽기 전용으로 점검할 수 있다.
- 대화형 검색 회귀 테스트는 개인화 힌트가 초점 필터를 우회하지 않는지, 명시 상태 질문이 부정 근거를 제외하는지, 후속 질문의 새 초점이 이전 일정/알림 도메인을 과도하게 상속하지 않는지 확인한다.

## 남은 과제

- public snapshot을 새로 발행할 때마다 문서와 운영 검증 문자열 최종 점검
- AI 답변 품질 평가와 비용 모니터링
- 다중 사용자 권한 모델 확장
- import/export 자동화 강화
